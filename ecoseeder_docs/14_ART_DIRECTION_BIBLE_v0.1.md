# 14 Eco Seeder v0.1 美术方向与资产规范（第一张地图范围）

## 1. 文档定位

本文件是 Eco Seeder 项目的美术方向基准，用于约束地图、场景、人物、NPC、机器人、UI、图标、特效和宣传画面的视觉设计。

本文件属于正式设计基线。任何 AI Agent、NPC、CodeBuddy、开发人员或素材提供者都不得自行改变本文件规定的整体美术方向。

如需调整美术风格，必须先提出变更建议，经项目负责人确认后修改本文件，再开展后续制作。

---

## 2. 核心美术方向

Eco Seeder 的整体视觉方向确定为：

> 半写实、2.5D、第三人称环境探索与生态养成游戏风格，以后工业污染区域和生态修复过程为主要场景，结合写实环境材质、自然生态元素和适量近未来环保科技元素。

目标画面应具有以下特征：

* 具有完整的游戏世界空间感，而不是单张宣传插画；
* 具有可探索、可交互、可养成的游戏场景感；
* 污染、废墟、自然生长和生态修复同时存在；
* 环境整体严肃但不绝望；
* 玩家能够从场景变化中感受到生态恢复过程；
* UI 与地图资产相互独立，不属于地图内容，也不直接绘制在地图中；UI 的视觉设计可以参考当前地图的色彩、材质和氛围，并可随着后续地图章节的开发迭代对应风格，但不得影响主要游戏内容的可见性和操作体验；
* 画面质量接近现代独立游戏或中型商业游戏的概念展示效果。

---

## 3. 风格关键词

### 3.1 正向关键词

项目美术应围绕以下关键词展开：

* 半写实；
* 2.5D；
* 第三人称探索；
* 后工业生态修复；
* 废弃工业设施；
* 污染水体；
* 自然重新生长；
* 冷灰蓝绿色调；
* 写实材质；
* 生态科技；
* 深色半透明 HUD；
* 环境叙事；
* 希望感；
* 轻度末世感；
* 可持续发展；
* 污染状态与修复状态对比。

### 3.2 禁止方向

不得采用以下视觉方向：

* 卡通绘本风；
* 儿童低龄插画风；
* Q 版或大头人物比例；
* 纯扁平网页插画风；
* 纯像素游戏风；
* 夸张赛博朋克霓虹风；
* 过度阴暗的恐怖末日风；
* 完全写实的摄影拼贴风；
* 高饱和糖果色风格；
* 不同地图、人物和页面采用互不一致的画风；
* 将完整 UI、中文文字和人物直接绘制在地图背景图中。

## 4. 参考图使用原则

### 4.1 正向参考

项目正向参考图应体现：

* 大范围环境场景；
* 明确的前景、中景和远景；
* 第三人称玩家角色；
* 可探索区域；
* 废弃工业结构与自然植被共存；
* 半透明游戏 HUD；
* 任务、资源和环境状态信息；
* 污染环境中的初步恢复迹象；
* 较高的场景纵深和空间尺度。

正向参考图只用于确定风格、构图、光照和信息布局，不得直接作为正式地图资产。

### 4.2 反向参考

此前由图片 NPC 生成的污染河道概念图不作为正式美术方向。

该方案存在以下问题：

1. 绘本感和卡通感过强；
2. 镜头距离过近；
3. 缺少大范围可探索空间；
4. 不具有完整游戏场景的纵深；
5. 人物和设备更接近插图元素，而不是可操作游戏对象；
6. 难以拆分为地图层、交互物和人物层；
7. 与项目期望的半写实第三人称游戏风格不一致。

该图仅保留为方案评估和人工否决记录。

## 5. 世界与环境设计

### 5.1 世界状态

游戏世界不是完全毁灭后的废土，而是仍有人居住、仍有治理可能的受损生态区域。

场景中应同时存在：

* 被废弃或低效运行的工业设施；
* 污染水体、垃圾、土壤退化和空气污染迹象；
* 仍在生长的先锋植物；
* 局部恢复的水体和植被；
* 环境监测设备；
* 生态修复设施；
* 居民、工作人员和任务 NPC；
* 小型机器人或智能生态助手。

### 5.2 环境叙事

场景应通过物体和环境状态表达背景，而不是依赖大量文字说明。

可使用：

* 生锈的管道和护栏；
* 破损厂房；
* 废弃排水口；
* 漂浮垃圾；
* 水面油污；
* 土壤开裂；
* 藤蔓覆盖的建筑；
* 新种植的树木；
* 生态监测装置；
* 净水设备；
* 太阳能设备；
* 居民修复活动；
* 修复前后的环境对比。

## 6. 地图与场景规范

### 6.1 MVP 地图范围

v0.1 只制作一张完整主地图：

```text
雾港旧工业区
```
该地图的程序内部 ID 为：

map.urban_wasteland

地图中的主要可玩区域为：

废弃工业湿地修复区

“废弃工业湿地修复区”是雾港旧工业区内部的主要区域，

地图至少包含：

* 废弃工厂区域；
* 污染河道；
* 排水口；
* 垃圾堆积区；
* 居民或修复人员活动点；
* 生态监测站；
* 水体净化设施；
* 初步恢复的植被区域；
* 一个重点任务区域；
* 一个 NPC 任务触发点。

v0.1 不开发大规模开放世界，不同时制作多个完整地图。

### 6.2 地图状态

同一地图至少支持两个状态：

```text
polluted
restoring
```

其中：

* `polluted`：污染较明显，垃圾较多，水体浑浊，植被稀疏；
* `restoring`：垃圾减少，水体改善，植被增加，修复设备开始运行。

后续版本可增加：

```text
restored
```

### 6.3 地图图层

正式地图不得只使用一张不可拆分的完整图片。

地图资产至少划分为：

```text
background/
midground/
foreground/
interactive/
effects/
collision/
```

各层含义：

| 图层            | 内容                   |
| ------------- | -------------------- |
| `background`  | 天空、远山、远处厂房和城市轮廓      |
| `midground`   | 河道、桥梁、厂房主体、大型植被和修复设施 |
| `foreground`  | 前景栏杆、草丛、垃圾和遮挡物       |
| `interactive` | NPC、垃圾、采样点、设备、任务对象   |
| `effects`     | 雨、雾、水面反光、漂浮颗粒和恢复光效   |
| `collision`   | 角色不可通过区域和交互边界        |

地图背景中不得直接绘制：

* HUD；
* 按钮；
* 中文标签；
* 任务文字；
* 玩家角色；
* NPC；
* 可交互道具。

这些内容必须由游戏代码独立加载和控制。

### 6.4 场景镜头

主场景采用轻俯视斜向第三人称表现：

- 玩家角色位于画面下方偏中位置；
- 玩家通常可以看到角色背面或三分之四背面；
- 主探索方向朝向场景中心和远景；
- 镜头不进行自由三维旋转；
- 场景具有明显前景、中景和远景；
- 地图通过二维分层和遮挡表现 2.5D 空间。

## 7. 玩家人物设计

### 7.1 基本角色

游戏提供：

* 一名男性玩家角色；
* 一名女性玩家角色。

两个角色具有相同的职业定位和能力，不设置能力差异。

### 7.2 角色风格

玩家角色应符合：

* 半写实比例；
* 约 7—7.5 头身；
* 年轻生态修复人员或环境调查员；
* 穿着适合户外调查和轻度工业环境的工作服；
* 携带背包、检测设备和基础修复工具；
* 服装具有自然绿色、灰色和低饱和橙色点缀；
* 不使用重型装甲；
* 不设计成军事角色；
* 不采用夸张英雄服装；
* 不采用 Q 版比例。

### 7.3 角色标准表

正式角色制作前应完成：

* 正面；
* 背面；
* 左右侧面；
* 三分之四视角；
* 标准站姿；
* 服装细节；
* 装备细节；
* 色板；
* 基础表情；
* 动作比例。

### 7.4 MVP 动作

v0.1 只要求：

```text
idle
walk
interact
collect
repair
```

每个动作可采用 4—8 帧序列帧，暂不制作战斗动画。
v0.1 保留冲刺操作，但不制作独立 `sprint` 序列帧。
冲刺复用 `walk` 动画，并提高动画播放速度和角色移动速度。

## 8. NPC 与机器人设计

### 8.1 NPC 类型

v0.1 实际制作和投放 3 名主要 NPC：

- 环境监测员；
- 当地居民或环保志愿者；
- 生态修复工程人员。

设计层的第 4 种职业原型只保留配置接口，不制作正式人物立绘、
场景角色、动画或专属资产。
NPC 应通过服装、工具和动作体现职业，不依赖夸张造型。

### 8.2 AI 生态助手

AI 生态助手采用小型机器人形象，负责：

* 新手引导；
* 环境提示；
* 任务建议；
* 污染数据解释；
* 修复反馈。

机器人设计应：

* 简洁；
* 友好；
* 具有环保科技感；
* 使用白色、深灰色和青绿色；
* 不使用过度儿童化表情；
* 不成为画面主角；
* 不模仿现有知名机器人角色。

## 9. UI 与 HUD 设计

### 9.1 基本原则

UI 必须服务于游戏场景，不能让游戏看起来像普通管理后台或网页信息系统。

UI 应具有：

* 深蓝黑半透明面板；
* 青绿色科技描边；
* 清晰的信息层级；
* 较低的视觉噪声；
* 适量圆角；
* 轻微发光效果；
* 明确的任务、资源和环境状态信息。

### 9.2 主场景 HUD

主场景 HUD 可包含：

顶部：

* 玩家身份和等级；
* 游戏日期；
* 天气；
* 时间；
* 生态点；
* 游戏货币；
* 背包、手册和设置入口。

左侧：

* 当前任务；
* 随机事件；
* 任务完成状态。

右侧：

* 环境监测数据；
* AI 生态助手提示。

底部：

* 核心功能导航；
* 主要交互按钮；
* 当前区域探索进度。

不得同时显示全部信息。不同状态下应收起不必要面板。

### 9.3 UI 禁止事项

不得：

* 将 UI 直接生成在背景图片中；
* 使用 AI 生成的模糊或错误中文；
* 同时使用多套不同风格按钮；
* 大面积遮挡地图；
* 使用高饱和霓虹边框；
* 使用过度复杂的玻璃拟态；
* 使用大量无功能装饰图标；
* 将所有功能都放在主界面。

## 10. Design Tokens

以下数值作为 v0.1 的候选设计变量，由后续 UI 实现验证后微调。

### 10.1 颜色

```text
--color-bg-deep: #081417;
--color-panel: rgba(8, 23, 26, 0.86);
--color-panel-light: rgba(19, 43, 46, 0.78);
--color-primary: #27D7C4;
--color-eco-green: #7ED957;
--color-reward: #F5B942;
--color-danger: #E85D5D;
--color-text-primary: #EAF4F2;
--color-text-secondary: #9FB5B2;
--color-border: #2A666A;
--color-disabled: #526361;
```

颜色用途：

* 青绿色：交互、生态修复和科技功能；
* 绿色：健康、完成和生态恢复；
* 黄色：奖励、货币和重要提醒；
* 红色：污染警告、失败和危险；
* 白色：主要文本；
* 灰绿色：次要文本。

### 10.2 圆角

```text
小型组件：6px
普通卡片：10px
大型面板：14px
圆形按钮：50%
```

### 10.3 描边

```text
普通描边：1px
强调描边：1.5px
禁止使用大面积粗描边
```

### 10.4 阴影与发光

只允许低强度阴影和局部青绿色发光。

发光只用于：

* 当前选中状态；
* 可交互对象；
* 任务目标；
* 环境修复设备；
* 重要提示。

## 11. 字体与文本

中文字体优先使用：

```css
"Noto Sans SC", "Microsoft YaHei", sans-serif
```

数字和英文可使用：

```css
Inter, "Noto Sans", sans-serif
```

要求：

* 正文可读；
* 不使用装饰性书法字体；
* 不使用过细字重；
* 正文不小于 14px；
* 重要 HUD 数值不小于 16px；
* 标题和正文层级明确；
* 中文文字必须由前端代码渲染，不写入背景图片。

---

## 12. 图标规范

图标应采用统一体系：

* 线性或轻度面性图标；
* 统一线宽；
* 统一圆角；
* 默认使用浅灰白；
* 选中状态使用青绿色；
* 奖励使用黄色；
* 警告使用红色。

不同来源的图标必须经过统一处理后再使用。

不得混用：

* 线性图标；
* 3D 图标；
* 卡通贴纸；
* 写实图片图标；
* 不同线宽的图标。

---

## 13. 光照与氛围

### 13.1 污染状态

污染状态使用：

* 冷灰色；
* 蓝绿色；
* 低饱和环境；
* 阴天或雨后光照；
* 潮湿地面反射；
* 轻微雾气；
* 局部暖色光源。

不得让场景黑到无法辨认。

### 13.2 修复状态

修复状态应体现：

* 更明亮的自然光；
* 更清晰的水面；
* 更丰富的绿色植被；
* 减少垃圾和污染痕迹；
* 修复设施正常运行；
* 鸟类、昆虫或居民活动增加。

修复前后必须保持相同主要地标和镜头方向，以便玩家感知变化。

---

## 14. 特效规范

MVP 可使用：

* 轻微雨滴；
* 水面波纹；
* 漂浮颗粒；
* 植物生长效果；
* 设备启动光效；
* 任务目标描边；
* 环境恢复粒子；
* UI 淡入淡出。

不得使用：

* 大规模爆炸；
* 强烈屏幕震动；
* 高强度闪烁；
* 过多粒子覆盖游戏画面；
* 与生态修复主题无关的战斗特效。

## 17. AI 与 NPC 使用边界

AI 图片工具或图片 NPC 可以用于：

* 风格探索；
* 色彩候选；
* 场景构图草案；
* 道具参考；
* 服装参考；
* 光照参考；
* 局部扩图；
* 裁剪和简单后处理。

AI 图片工具不得直接决定：

* 项目整体画风；
* 最终地图结构；
* 最终人物标准形象；
* HUD 信息架构；
* 正式中文文字；
* 全部动画；
* 多场景角色一致性。

AI 生成的完整游戏截图默认视为概念参考，不直接作为正式可运行资产。

任何 AI 输出必须经过人工审查后才能进入项目。

## 18. v0.1 美术资产范围

v0.1 只要求完成：

* 1 张主地图；
* 同一主地图的污染和初步修复状态；
* 男、女玩家角色各 1 名；
* 3 名主要 NPC；
* 1 个 AI 生态助手；
* 15—20 个核心图标；
* 主场景 HUD；
* 任务面板；
* NPC 对话框；
* 任务完成弹窗；
* 设置面板；
* 少量环境和交互特效。

暂不制作：

* 多张完整地图；
* 大量 NPC；
* 复杂换装系统；
* 高成本剧情动画；
* 完整开放世界；
* 大量人物配音；

## 19. 美术验收清单

任何资产进入正式版本前必须确认：

* 是否符合半写实生态修复风格；
* 是否与正向参考方向一致；
* 是否存在卡通绘本化问题；
* 是否与其他资产保持同一画风；
* 是否可以独立替换和复用；
* 是否具有清晰图层或透明背景；
* 是否包含错误文字；
* 是否存在版权风险；
* 是否记录素材来源；
* 是否适合网页端加载；
* 是否影响页面性能；
* 是否具有污染与修复状态对应关系；
* 是否经过项目负责人确认。

## 20. 变更控制

美术方向的修改必须遵循：

```text
提出变更建议
→ 分析影响范围
→ 项目负责人确认
→ 修改本文件
→ 提交 Git Commit
→ 更新相关资产
```

任何 NPC、CodeBuddy 或开发人员不得绕过本文件直接改变美术风格。
